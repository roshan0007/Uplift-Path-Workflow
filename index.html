How we build & ship Uplift Path
Timeline
One straight line, then it loops

Every idea moves down this same pipeline, in order. Once the site is live, new changes don't get a separate process — they re-enter at step 05 and flow through the same steps again.

Design phase
01
Input

Brand guidelines → v0

Uplift Path's brand guidelines — colors, type scale, logo rules, tone, the AA-contrast bar — were already built. We uploaded them straight into v0's design system feature, so v0 starts from a structured source of truth instead of a text prompt.

brand guidelinesv0 design system
02
AI generation

v0 generates the project

Using that same uploaded design system, v0 generated a full Next.js + Tailwind project — hero, values grid, dark band, stats, testimonial, CTA — matched to the brand automatically, refined over a few chat-to-UI passes.

v0.devNext.jsTailwind
Why v0 first? Fastest way to get a real, on-brand UI in front of the team before any hand-written code exists.
03
Design system

v0 generates the design agent

From the same guidelines, v0 also generated a dedicated design agent for Uplift Path — a packaged reference of tokens, components and hard rules (e.g. never white text on brand teal), instead of just a one-off page.

v0.devdesign tokensdesign agent
Build phase
04
Development

Export → Claude Code

The project and the design agent are exported from v0 and installed as a Claude Code skill at .claude/skills/uplift-path/ inside the real repo. Claude Code becomes the build agent — implementing header, homepage and pages against it as the single source of truth.

Claude CodeNext.js 16React 19TypeScript
Why hand it to Claude Code? Claude Code reads the design agent on every edit, so tokens and rules stay enforced automatically instead of drifting between sessions.
05
Development

Iterate & QA loop

The everyday change loop: edit code → run the dev server → check it in a live browser preview → fix bugs and contrast issues → re-verify. Settled decisions get written back into the skill so they aren't relitigated.

next devbrowser previewpnpm
Ship
06
Version control

Push to GitHub

Once changes are edited and verified locally, they're committed and pushed to the GitHub repo — the single trigger for everything that happens next.

git pushGitHub
07
Infra / deploy

Auto build & deploy

Cloudflare Workers Builds watches the repo. Every push to main runs the build command, then npx wrangler deploy, automatically inside Cloudflare's own build environment — no manual deploy step.

Cloudflare Workers BuildsWrangler
Why auto-deploy on push? Every merge to main goes straight to production — nobody has to remember to run a deploy command by hand.
08
Output

Live site

Uplift Path running in production on Cloudflare's edge.

production
